# Real disruption alerts, synthetic forwarder data on a simulated clock

No public dataset contains a forwarder's Shipments, Customers, contracts, revenue and carrier cost, so the forwarder (Customers, Lanes, Voyages, Shipments, prices) is generated by our own simulator. Observed Disruptions come from real public feeds (GDACS for volcanoes, cyclones and floods; USGS for earthquakes) so the demo reacts to the actual world, and Chokepoint closures and port strikes are Injected Disruptions, always labelled as simulated. The simulator advances a Simulated Clock (configurable, e.g. 1 real minute = 1 simulated hour) so vessels visibly move in a 3-minute video.

## Considered Options

- **Live AIS vessel positions (aisstream.io)**: real ships, and it reuses the Helsinki custom streaming source, but it needs a second ingestion build in a 7-day window, a continuous pipeline (Helsinki: ~$6/h), and real vessels still carry no Shipments. Kept as a post-hackathon option.
- **Fully synthetic, including disruptions**: cheapest, but the jury weights industry relevance and "real" heavily.

## Consequences

- The SLA-breach model learns patterns the simulator put in. The write-up says so openly and explains that the same pipeline would retrain on a forwarder's real TMS history.
- Customer, carrier and vessel names are fictional, while ports, airports and Chokepoints are real, so the demo never implies facts about real companies.
